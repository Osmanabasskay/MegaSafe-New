# Mi Osusu Group Management Feature Specification

## Goal

Modify the Osusu group area so that every group has a clear internal structure similar to a WhatsApp group screen, but designed for a financial savings group.

The main group screen should show the group details, members, ledger, invite settings, group settings, activity, and delete group actions based on the user's role.

The app must maintain Mi Osusu branding:

- Primary color: Orange `#F97316`
- Dark color: `#0F172A`
- Background: `#FFFFFF`
- Currency: `NLe`
- Style: Clean, mobile-first, no unnecessary borders, no heavy shadows, no AI icons, no emojis.

## Three-Dot Menu Options

### Normal Member

- Group Info
- Members
- Ledger
- Invite Settings
- Leave Group

### Admin / Creator

- Group Info
- Members Management
- Ledger
- Activity
- Invite Settings
- Group Settings
- Delete Group

## Access Rules

### Members

Can:

- View group information
- View members
- View ledger summaries
- View their contribution records
- Leave group (if eligible)

Cannot:

- Manage members
- Access activity logs
- Change settings
- Delete group

### Admins

Can:

- Manage members
- View ledger
- Configure invites
- Change settings
- View activity logs

Cannot:

- Delete group unless creator

### Creator

Can perform all actions including group deletion.

# 8. Delete Group

## Purpose

Allows creators to permanently remove a group.

## Access

Creator only.

## Eligibility Requirements

- No pending contributions
- No pending payouts
- No disputes
- No active transactions
- No unpaid cycles
- No pending join requests
- No settlement issues

## Delete Flow

```text
Delete Group
└── Eligibility Check
    ├── Fail
    │   └── Show blocking reasons
    └── Pass
        └── Confirmation
            ├── Accept warning
            ├── Type group name
            ├── PIN/Biometric verification
            └── Archive group
```

## Soft Delete Strategy

```text
group_status = deleted
deleted_at
deleted_by
invite_disabled = true
members_access_revoked = true
```

Financial records remain for audit purposes.

# 9. Leave Group

## Conditions

Members can leave only if:

- No pending contributions
- No pending payouts
- Not current collector
- No unresolved disputes
- Group settings allow leaving

## Flow

```text
Leave Group
└── Eligibility Check
    ├── Fail
    │   └── Show reason
    └── Pass
        ├── Confirmation
        ├── PIN verification
        ├── Remove member
        └── Activity log created
```

# 14. Security Requirements

- Use Supabase Edge Functions or secure RPC.
- Never calculate balances on frontend.
- Enforce RLS on all group tables.
- Verify membership before actions.
- Verify roles before actions.
- Generate audit logs for all financial and administrative actions.
- Require confirmations for destructive actions.
- Require PIN or biometric verification for high-risk actions.
